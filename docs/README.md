## 📖 Documentation Standards

### Quality Guidelines

Our documentation follows these principles:

1. **Clarity** - Clear, concise language
2. **Completeness** - Comprehensive coverage
3. **Accuracy** - Up-to-date and correct
4. **Examples** - Code samples and diagrams
5. **Navigation** - Easy to find information

### File Naming Convention

- **UPPERCASE.md** - Major documents (README, CONTRIBUTING)
- **lowercase-with-hyphens.md** - Topic documents (architecture, flows)
- **Subdirectories** - Related content grouped (sdk/, product/, whitepaper/)

### Formatting Standards

- Markdown for all documentation
- Table of contents for long documents
- Code blocks with language specification
- Mermaid diagrams for flows
- Emoji icons for visual hierarchy
